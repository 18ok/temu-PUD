1. 收束数据管线

Strong local-substitutable

extractProducts() · doClustering() · extractRules() · checkAvoidance() · normalizeCols()

Before — 5 shallow modules

extractProducts ← interface = ST.files → products (1:1)
doClustering ← interface = products → clusters (1:1)
extractRules ← interface = clusters → rules (1:1)
checkAvoidance ← interface = products → issues (1:1)
normalizeCols ← hardcoded map, 1 adapter

After — 1 deep module

DataPipeline
analyze(files) → { products, clusters, rules, avoidance }
─ normalizeCols ─ scoring ─ threshold calc ─
internal seams, private to module
interface: 1 call · implementation: 5 passes

Problem: 5个函数逐个调用全局ST，interface 和 implementation 几乎 1:1 对应。每加一个分析维度就多一个 function signature。

Solution: 收束为一个 DataPipeline module，单一入口 analyze(files) 返回结构化结果。

  • leverage: 5 call sites → 1 interface
  • locality: bugs in scoring concentrate in one module
  • interface shrinks; implementation absorbs normalization + clustering

Problem: 每个页面都是独立的~100行 innerHTML 拼接函数。Plotly 调用散布在 renderProducts 和 renderDiagnosis 中，跨模块泄漏。

Solution: 提取 template 工具函数（card、table、expander），每个页面退化为 20-40 行的数据→模板映射。Plotly 抽成 adapter。

  • leverage: cardTemplate serves 6 pages from 1 interface
  • locality: Plotly config lives in one adapter, not two renderers
  • two adapters justify the Plotly seam: scatter + trend

3. 快照对比模块化

Worth exploring local-substitutable

compareSnapshots() · suggestPruning() · generateDirectionAdvice()

Before — 3 calls, each loads localStorage independently

compareSnapshots
17-property return
4 localStorage reads
mixed concern
suggestPruning
3 rule checks
re-extracts old products
re-scores
generateAdvice
6 if-branches
hardcoded thresholds
mixes data + prose

After — 1 deep module, 1 interface

DiagnosisEngine
analyze(snapshots, products) → { comparison, pruned, advice }
─ compareSnapshots ─ suggestPruning ─ generateAdvice ─
internal seams · one localStorage read at entry · pure functions inside

Problem: compareSnapshots 返回 17 个属性的巨对象。suggestPruning 重新调用 extractProducts + localStorage。三个函数各自独立但共享输入。

Solution: 收束为 DiagnosisEngine.analyze(snapshots, products)，内部 pure functions，不再碰 localStorage。

  • leverage: 3 call sites → 1 interface
  • locality: threshold tuning hits one place
  • interface shrinks from 17 fields to 3 structured result objects

After — CSS modules with seams

interface: sidebar + main + topbar

Problem: 280行 CSS 内联在 HTML 中，修改一个组件的样式必须翻整个文件。没有 seam，无法独立测试或替换。

Solution: 拆为 design-tokens.css + components.css + layout.css，用 <link> 加载。

  • leverage: one design-tokens.css serves all components
  • locality: color changes stop at :root
  • deletion test: delete design-tokens.css → chaos in 30 classes = it earns its place
⚠ 低优先级。当前单文件便于分发；只有需要多人协作或频繁调整样式时才值得拆。
