# 商品画像归因模板 V1

## 定位

本模板用于把“商品表现分层”升级为“商品经营归因”。聚类只能做初筛，不能直接说明一个品为什么爆、为什么亏、还能不能继续做。后续 Temu 系统和 SHEIN 系统都应围绕同一套商品经营字段沉淀数据，但各平台保留独立口径和独立系统入口。

## 核心判断路径

1. 先看结果：销量、利润、ROAS、退款、库存、生命周期。
2. 再问原因：产品、价格、流量、供应链、平台规则、竞品环境分别贡献了什么。
3. 再给动作：继续放量、维持、降本、改图、调价、清仓、避开品类。
4. 最后沉淀规则：哪些特征值得复用，哪些特征应进入避坑清单。

## 爆品归因

爆品不能只写“销量高”。至少需要回答：

- 它好在哪里：价格优势、图文卖点、功能差异、类目趋势、供应链稳定、平台扶持、广告效率。
- 它处在哪个阶段：新品起量、稳定放量、竞争加剧、衰退清仓。
- 它怎么维持：补货节奏、供应链降本、素材复用、价格带防守、同类扩品。
- 它的风险是什么：退款抬头、竞品跟进、平台规则变化、库存断货。

## 差品归因

差品不能只写“毛利低/销量低”。至少需要回答：

- 是产品本身不行，还是运营动作不匹配。
- 是市场需求弱，还是平台流量变了。
- 是价格没有竞争力，还是成本结构不成立。
- 是图片/标题/卖点表达弱，还是供应链/履约/质量拖累。
- 后续如何减少再发生：禁入特征、类目黑名单、最低利润线、投流止损线。

## 图片与公司数据边界

- 允许运行时使用公司商品图片和运营数据。
- 代码仓库只保存字段结构、模板和空样例，不保存真实公司数据。
- 图片字段优先存 `image_url`，必要时存本地缓存路径，但必须能一键剥离。
- 导出给外部人员时，默认脱敏商品名、供应商、店铺和真实成本。
