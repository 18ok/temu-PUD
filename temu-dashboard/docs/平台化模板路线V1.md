# 平台化模板路线 V1

## 结论

不建议直接废弃现有 Temu 双表链路。

更稳的做法是：

- 现有两份 Temu 表格降级为 `Temu 适配器`
- 新增统一的 `跨境经营诊断模板`
- Temu / SHEIN 各自有一套平台模板
- 系统内部统一转成同一套商品经营诊断模型

也就是：

`平台原始表 -> 平台适配器 -> 统一经营模型 -> 亏损品池 / 爆品复盘 / 规则沉淀`

## 为什么不能马上摈弃旧双表

旧双表虽然业务深度不够，但有三个价值：

- 已经跑通导入、解析、团队对齐分、OSS 同步
- 能提供 Temu 当前真实经营数据入口
- 可以作为新模型的迁移对照组

如果立刻废掉，风险是：

- 当前可用链路断掉
- 新模板还没被团队真实填写验证
- 业务判断和代码同时大改，出问题难定位

所以旧双表应该变成历史兼容入口，而不是系统的未来上限。

## 产品命名

当前系统不应再叫 `Temu 团队看板`。

建议统一为：

`跨境经营诊断系统`

定位：

- 多平台
- 多店铺
- 团队协作
- 商品经营诊断
- 爆品复盘
- 亏损品池
- 规则沉淀

Temu / SHEIN 是平台适配层，不是产品本体。

## 看板入口设计

侧栏品牌区下方增加折叠入口：

- `Temu 诊断模板`
- `SHEIN 诊断模板`

入口默认折叠，避免干扰主导航。

用户逻辑：

- 做 Temu：下载或使用 Temu 模板
- 做 SHEIN：下载或使用 SHEIN 模板
- 系统内部仍按统一字段做诊断

## 模板文件

当前已放置：

- `docs/templates/Temu商品经营诊断模板V1.xlsx`
- `docs/templates/SHEIN商品经营诊断模板V1.xlsx`

说明：

- Temu V1 兼容现有利润统计 / 店铺数据路径
- SHEIN V1 先沿用统一经营诊断模型
- 后续再补 SHEIN 独有字段，例如供货模式、履约周期、平台活动、佣金/扣费、退供风险等

## 后续平台适配器方向

### Temu 适配器

输入：

- 店铺利润统计 `.xls`
- 店铺数据记录 `.xlsx`
- 后续新经营诊断模板

输出统一字段：

- 商品基础
- 每日表现
- 运营动作
- 问题诊断
- 亏损品池
- 爆品复盘

### SHEIN 适配器

输入：

- SHEIN 商品表现表
- SHEIN 订单 / 履约 / 结算表
- SHEIN 经营诊断模板

需要补充重点：

- 供货模式
- 履约周期
- 退供 / 退货
- 平台活动
- 扣费结构
- 库存周转
- 供应链稳定性

## 技术落点

前端：

- 品牌名改为 `跨境经营诊断系统`
- 侧栏品牌区下方放平台模板折叠入口
- 后续导入页增加平台选择：`Temu / SHEIN / 通用模板`

后端：

- 不按平台拆数据库主表
- 按统一经营模型建表
- 平台差异放到 adapter 层和扩展字段

数据库：

- `platform`
- `source_file_type`
- `source_platform_fields`
- `normalized_product_id`
- `spu_id`
- `sku_id`

这样既能兼容不同平台，又不会每个平台做一套孤岛系统。
