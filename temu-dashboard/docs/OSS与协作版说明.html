很多人问：「团队对齐分和团队协作到底是什么关系？」
简短回答：团队协作是主线，团队对齐分是体系里的个人成长镜子。OSS 摘要同步是第一阶段，后续会继续扩展到团队登录、分组和主管团队看板。

一、试用版里已经有什么（✅ 能用）

已有团队对齐分

在本机导入 利润统计 .xls + 数据记录 .xlsx → 左侧 🏆 团队对齐分 → 看 0–100 对齐分。不需要云端。

已有云端摘要同步（网页版填 Key，或 bat + .env 托管）

每人本地 Excel → 系统打成 JSON 摘要（不是原始 Excel） → ⚙ 管理后台 → ⬆ 同步团队 到 OSS（按「归属人」区分） → 📥 团队基准 拉同事最新摘要 → 主要用于「团队选品基准」、诊断里个人 vs 团队对比

原始 Excel 不会 整表上传，只传处理后的 JSON 摘要。V10.4 起同步入口在 管理后台，不在侧栏单独放 OSS 按钮。

本地 bat协作 API 骨架（api_server.py）

双击 启动本地看板.bat 后，管理后台可看到后端状态、同步记录、审计日志，以及 🔐 团队登录 入口。这是下一阶段能力的本地预览，GitHub Pages 网页版仍以 OSS 摘要同步为主。

二、为什么先做对齐分，再进入团队看板

对齐分页上的 「主管团队看板」 按钮指的是下一阶段团队协作能力。它不是独立于个人之外的“另一个产品”，而是把每个人的对齐分放回小组和主管视角里：

  • 主管在一个页面看 多个人各自 的对齐分（「谁该辅导」视图）
  • 对齐分页里的 团队 PK 对比表（不是个人镜子，而是多人并排）
  • 发一个链接，对方 不用导 Excel 就能看团队汇总（服务端部署后能力）

分阶段开放当前先让每个人跑通双 Excel 和团队摘要同步；主管团队看板需要服务端和身份体系稳定后再扩大使用。

当前真实状态：代码里已有协作注册 / 登录、分组、主管团队 PK、SQLite 索引等骨架；本地 bat 可预览部分后台能力。接下来不是把它藏起来，而是先把摘要同步和对齐分稳住，再按 ECS 部署节奏把团队协作能力逐步放大。

四、为什么「有 OSS」还不够？

对比项 现在的 📥 团队基准 团队协作路线
拉下来是什么 同事的 选品 SPU 列表，拼成团队基准 每人完整的 对齐分 / 双管线摘要
主要用在哪 诊断、商品画像等「个人 vs 团队基准」 对齐分页「主管团队看板」、主管看谁要帮
对齐分页会变吗 不会 — 仍只算你自己本机两份 Excel 会 — 个人分数进入小组 / 主管视图
身份 归属人自己填名字（试用够用） 需团队登录 / 邀请码 / 受控部署（保证归属和权限准确）
操作入口 ⚙ 管理后台 → 同步团队 / 团队基准 管理后台 + 团队账号 + 主管视图
技术原因（给好奇的同事）： 团队对齐分用的是本机完整店铺字段（如 ctr、cvr 等）；云端摘要里的店铺字段较少，且 📥 团队基准目前只合并选品侧，不够在云端直接算每个人的对齐分。所以：同事都同步了，你的对齐分页仍然只是你自己的分——这是设计如此，不是 bug。

  • 在 GitHub Pages 上强行期待完整协作账号流程

六、和「使用限制」的关系

压缩包里的 组员使用说明.html §七 写了完整使用限制。和本文相关的核心一句：

对齐分 = 团队协作下的个人成长镜子，不是考核淘汰排名。 云端同步是团队协作第一阶段，完整主管看板会按部署节奏开放。

七、有问题找谁

  • 打不开 / CORS → 优先用 https://18ok.github.io/temu-PUD/；勿直接双击 HTML。无网或无 CORS 时用 启动本地看板.bat
  • 找不到 OSS 按钮 → V10.4 已迁入 ⚙ 管理后台
  • 对齐分空白 → 两份 Excel 都要在团队工作台导入
  • 同步失败 → 管理后台 → 同步配置；或找玉成要 Key / .env；暂只用本地对齐分也可
  • 功能建议 → 反馈给玉成
