# 商品经营诊断数据模型 V1

> 目标：把当前“商品数量统计看板”升级为“跨境 Temu 商品经营诊断系统”的数据底座。  
> 核心问题不是有多少黄金品，而是：为什么爆、为什么亏、下一步怎么做、经验如何沉淀给团队。

## 一句话定位

这套模型围绕“团队协作下的个人成长”设计：

`商品基础 -> 每日表现 -> 运营动作 -> 问题诊断 -> 规则沉淀 -> 爆品复盘 / 亏损品池`

它要让系统从“展示结果”升级为“解释原因 + 给出动作 + 沉淀规则”。

## 为什么现有表不够

现有双 Excel 主要能支撑：

- 商品利润、毛利率、日销、成本、克重等基础指标
- 店铺侧 ROAS、利润率、订单等运营指标
- 个人与团队基准的对齐分

但它还不能可靠回答：

- 一个品爆单，是自然流量、广告、活动、主图、价格、类目趋势还是供应链导致？
- 一个品亏钱，是产品不行、类目不行、平台调整、退款过高、广告烧钱还是运营误判？
- 调价、换图、换标题、投放、参加活动后，到底有没有产生正向结果？
- 哪些坑应该沉淀成规则，避免团队新人重复踩？

所以必须补齐“原因”和“动作”两层数据。

## 表 1：商品基础表

用途：定义商品身份、类目、图片、成本、供应链与视觉基础。

关键字段：

- `spu_id`
- `sku_id`
- `商品名称`
- `大类`
- `小类`
- `细分类目`
- `平台类目`
- `上架日期`
- `生命周期阶段`
- `供应商`
- `采购成本`
- `包装成本`
- `头程/物流成本`
- `平台售价`
- `活动价`
- `目标毛利率`
- `是否定制品`
- `是否季节品`
- `侵权风险`
- `主图链接`
- `场景图链接`
- `细节图链接`
- `竞品链接`
- `商品标签`
- `视觉标签`
- `供应链备注`
- `负责人`

业务价值：

- 图片链接用于后续爆品视觉共性分析、亏损品池展示、竞品视觉对比。
- 大类 / 小类 / 细分类目用于沉淀“哪些类目适合做，哪些类目容易亏”。
- 成本结构用于判断一个品是天生利润薄，还是运营动作导致亏损。

注意：

- 图片先填 URL，不把图片嵌入 Excel。
- 后续系统可以把图片 URL 缓存到 OSS，但 Excel 不承担图片存储。

## 表 2：每日表现表

用途：记录每天或每周的经营结果。

关键字段：

- `日期`
- `spu_id`
- `曝光量`
- `点击量`
- `点击率`
- `访客数`
- `加购数`
- `下单数`
- `支付件数`
- `销售额`
- `退款件数`
- `退款金额`
- `退款率`
- `广告花费`
- `广告订单`
- `ROAS`
- `采购成本合计`
- `物流成本合计`
- `平台费用`
- `净利润`
- `库存`
- `动销率`
- `自然流量占比`
- `活动标记`
- `平台流量变化`
- `备注`

业务价值：

- 区分“卖得多”和“赚得多”。
- 区分“自然爆单”和“广告烧出来的假繁荣”。
- 判断亏损来自广告、退款、成本、库存还是转化。

核心判断示例：

- 销量上涨但净利润下降：先查广告花费、活动价、退款率。
- 点击率高但转化低：优先查价格、评价、主图承诺与商品详情是否错位。
- ROAS 高但库存不足：优先处理供应链与补货，不要盲目扩投。

## 表 3：运营动作表

用途：记录人做过什么，这是因果分析的核心。

关键字段：

- `动作日期`
- `spu_id`
- `操作人`
- `动作类型`
- `动作说明`
- `调价前`
- `调价后`
- `是否换主图`
- `是否换标题`
- `是否参加活动`
- `广告预算前`
- `广告预算后`
- `库存动作`
- `预期目标`
- `观察窗口`
- `复盘状态`
- `复盘结论`

业务价值：

- 没有动作记录，系统只能看到结果，不能解释原因。
- 动作表能回答：爆单或亏损之前，我们到底做过什么。
- 后续可用于判断哪类动作最有效，例如换图、调价、停投、活动、扩 SKU。

最低要求：

- 调价、换图、改标题、投放、参加活动、停投、下架必须记录。
- 每个动作要写观察窗口，例如 3 天、7 天、14 天。

## 表 4：问题诊断表

用途：把亏损、退款、异常、违规拆成可行动原因。

关键字段：

- `发现日期`
- `spu_id`
- `问题类型`
- `严重程度`
- `亏损金额`
- `主要原因`
- `二级原因`
- `是否产品问题`
- `是否市场问题`
- `是否平台规则问题`
- `是否供应链问题`
- `是否运营动作问题`
- `证据数据`
- `处理方案`
- `处理状态`
- `复盘结论`
- `是否加入避坑池`

业务价值：

- 亏损不是一个原因，必须拆来源。
- 同样亏 100 元，原因可能完全不同：
  - 产品本身无优势
  - 类目竞争突然变强
  - 平台活动压价
  - 广告误投
  - 供应链质量导致退款
  - 主图承诺过强导致差评

系统未来可自动输出：

- 产品问题：建议停上同类款 / 改供应链 / 下架止损。
- 市场问题：建议观察竞品价位 / 暂停扩款 / 降低库存。
- 平台规则问题：建议加入避坑规则 / 检查标题和图片合规。
- 运营动作问题：建议回滚动作 / 复盘操作人策略。

## 表 5：规则沉淀表

用途：把一次复盘变成团队长期资产。

关键字段：

- `规则ID`
- `规则名称`
- `规则类型`
- `适用大类`
- `适用小类`
- `触发条件`
- `判断逻辑`
- `风险等级`
- `推荐动作`
- `反例商品`
- `优秀案例商品`
- `生效日期`
- `维护人`
- `复核周期`
- `备注`

业务价值：

- 让新人不靠感觉选品。
- 让团队从“个人经验”变成“共同规则”。
- 让系统逐步有自己的运营判断能力。

示例规则：

- 毛利率低于 20%，退款率高于 8%，ROAS 低于 2.5，连续 3 天净亏损，进入止损观察。
- 点击率高但转化低，优先检查价格、评价、详情承诺和主图一致性。
- 某小类连续 5 个商品进入亏损品池，暂停该小类扩品。

## 表 6：亏损品池

用途：集中管理赔钱、接近赔钱、反复异常的商品。

关键字段：

- `入池日期`
- `spu_id`
- `商品名称`
- `大类`
- `小类`
- `细分类目`
- `主图链接`
- `近7天净利润`
- `近7天退款率`
- `近7天ROAS`
- `动销率`
- `亏损状态`
- `亏损原因标签`
- `建议动作`
- `责任人`
- `处理截止日`
- `处理结果`
- `复盘结论`

业务价值：

- 把亏损品按类目和图片集中看，团队能快速形成避坑直觉。
- 新人可以通过亏损品池学习“哪些品看起来能做，其实容易亏”。
- 后续系统可自动推荐：停投、调价、清库存、下架、加入避坑规则。

建议页面形态：

`大类 -> 小类 -> 细分类目 -> 商品图片 -> 亏损原因 -> 建议动作`

## 表 7：爆品复盘

用途：拆解爆品成因和维持动作。

关键字段：

- `复盘日期`
- `spu_id`
- `商品名称`
- `大类`
- `小类`
- `细分类目`
- `主图链接`
- `爆发时间`
- `爆发类型`
- `核心优势`
- `流量来源`
- `转化优势`
- `价格优势`
- `供应链能力`
- `风险点`
- `维持动作`
- `复制动作`
- `负责人`
- `下次复盘日期`

业务价值：

- 爆品不是庆祝销量，而是拆可复制经验。
- 系统必须区分：
  - 自然爆
  - 广告推爆
  - 活动带爆
  - 平台趋势带爆
  - 主图/标题优化带爆
  - 供应链优势带爆

后续动作：

- 能维持：补库存、稳价格、监控退款、维护评价。
- 能复制：扩同类、扩 SKU、复制视觉结构、复制关键词。
- 有风险：供应链不足、退款上升、平台流量不稳定、竞品跟价。

## 图片链接是否必须加

建议加，而且要尽早加。

图片不是为了美观，而是为了：

- 爆品视觉共性复盘
- 亏损品视觉问题复盘
- 竞品对比
- 新人训练
- 后续 AI 识图 / 图片缓存 / 类目视觉规则

当前阶段只需要 URL：

- `主图链接`
- `场景图链接`
- `细节图链接`
- `竞品链接`

后续如果图片多：

- 原图 / 缓存图放 OSS
- 数据库只存 URL、图片哈希、抓取状态、视觉标签
- 前端展示缩略图

## 入库建议

当前 Excel 模板是业务模型，不是最终数据库结构。

后续数据库建议拆成：

- `products`：商品基础
- `product_daily_metrics`：每日表现
- `operation_actions`：运营动作
- `diagnosis_cases`：问题诊断
- `rules`：规则沉淀
- `loss_pool`：亏损品池
- `winner_reviews`：爆品复盘
- `product_images`：图片 URL / OSS 缓存 / 视觉标签

OSS 继续负责：

- 图片缓存
- 原始导出文件
- 大 JSON 摘要
- 报告附件

数据库负责：

- 查询
- 权限
- 诊断
- 复盘
- 规则
- 团队协作

## 下一步代码方向

建议按以下顺序进入实现：

1. 扩展 `normalizeCols()`，支持图片链接、大类、小类、细分类目、净利润、退款率、广告花费、ROAS、库存等字段。
2. 扩展 `extractProducts()`，让商品对象承载图片、类目路径、经营结果和风险标签。
3. 新增 `loss_pool` 数据结构，先从本地数据中筛选亏损/接近亏损商品。
4. 新增亏损品池页面卡片：图片 + 类目路径 + 亏损原因 + 建议动作。
5. 新增爆品复盘页面：流量、转化、利润、供应链、复制动作。

## 判断标准

这个模型成功的标志不是字段多，而是系统能开始回答：

- 这个品为什么好？
- 好在哪里？
- 后续怎么维持？
- 能不能复制？
- 这个品为什么亏？
- 是产品、市场、平台、供应链还是运营动作的问题？
- 下次怎么少踩坑？

如果回答不了这些问题，就继续补数据，不急着堆 UI。
