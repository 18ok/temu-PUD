# 阿里云部署路线 V1

目标：先把 Temu 子系统从本机试点迁到可协作的阿里云 MVP，再逐步升级为正式协作版。起步方案推荐单 ECS 或轻量应用服务器 + `api_server.py` + SQLite + OSS。

## 1. 本机试点

- 前端：`temu-dashboard.html` / `temu-dashboard-editorial.html`
- 服务：本机运行 `api_server.py`，默认 `http://localhost:8080`
- 存储：浏览器 localStorage 保存个人工作状态；OSS 保存团队 JSON 摘要；SQLite 保存协作账号、小组、审计和 PK 索引
- 边界：原始 Excel 不上传云端；同步只上传结构化摘要和必要的图片 URL 字段

验收：

- `python api_server.py` 可启动
- `/api/status` 返回正常
- 管理后台能检测到后端服务、OSS 配置和协作数据库
- 商品画像能展示主图覆盖率、评价图覆盖率和缺图数量

## 2. 阿里云 MVP

推荐配置：

- 一台阿里云 ECS 或轻量应用服务器
- Python 运行 `api_server.py`
- SQLite 继续作为第一阶段协作数据库
- 阿里云 OSS 保存团队摘要、导出文件和后续图片缓存
- Nginx 或宝塔反代到 `TEMU_API_PORT`
- 域名开启 HTTPS，前端用公开 API 地址访问协作服务

关键环境变量：

```env
TEMU_API_HOST=0.0.0.0
TEMU_API_PORT=8080
TEMU_PUBLIC_API_BASE=https://api.example.com
TEMU_OSS_BUCKET=temu-shujufenxi-data
TEMU_OSS_REGION=oss-cn-hangzhou
TEMU_OSS_PREFIX=temu/
TEMU_WORKSPACE_ID=default
TEMU_COMPANY_ID=personal
TEMU_PROJECT_ID=temu
TEMU_PLATFORM=temu
TEMU_DATA_SENSITIVITY=company_internal
TEMU_JWT_SECRET=change-me-to-a-long-random-string
```

上线顺序：

1. 在服务器创建代码目录和 `.env`。
2. 安装 Python 依赖，启动 `api_server.py`。
3. 配置 Nginx HTTPS 反代到本地端口。
4. 在前端管理后台检查 OSS、协作数据库、域名 HTTPS、团队登录。
5. 用普通运营、组长/主管、管理员三类账号各跑一次同步和查看流程。

## 3. 正式协作版

当团队稳定使用后，再升级以下能力：

- SQLite 迁 PostgreSQL，支持更强的多人并发和备份恢复
- OSS 图片缓存，把外部主图 / 评价图 URL 逐步缓存到公司 OSS
- 角色权限固化为服务端策略：普通运营、组长/主管、管理员、开发者四档
- 公司经营总览只展示小组与平台汇总，不展示个人原始明细
- 建立每日备份、回滚脚本、审计导出和离职数据剥离流程

正式版验收：

- HTTPS 可用，浏览器不再访问 localhost
- 管理后台部署链路四项全部通过
- 团队同步只包含摘要和必要 URL，不包含原始 Excel
- 老板总览能看到小组成绩、平台状态、图片数据质量和协作服务状态
